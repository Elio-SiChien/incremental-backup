# 全局 Codex 增量备份 Skill 方案

## 使用目标

以后直接告诉 Codex：

> 把 `G:\Project` 新增和改动的文件备份到 `H:\Project`，保留旧版本。

Codex 根据请求自动选择 `incremental-backup` 技能，提取源和目标路径、匹配本地配置、预览，然后执行已授权的备份与校验。
也可显式写 `$incremental-backup`。只问“看看差异”就只预览；明确说“备份/复制更新”就按该指令执行，不重复询问。
如果只提供硬盘根目录，使用其下与源文件夹同名的子目录，并告知最终路径；路径或方向不清楚时只补问缺失项。

## 它与 rclone 有什么区别

rclone 是底层文件传输与比较工具。本项目是基于它的本地备份操作层，加上 Codex 的自然语言调用规则。
**文件比较、复制、传输重试、校验能力来自 rclone，本项目不声称发明了新备份算法，也没有修改 rclone 源码。**

| 层面 | 直接使用 rclone | 本项目与全局 Skill |
|---|---|---|
| 用户输入 | 自己编写命令、参数及源目标路径 | 用自然语言给出两个路径，Codex 选择固定备份流程 |
| 增量比较/传输 | rclone 的原生能力 | 调用相同能力，不增加独立复制引擎 |
| 不删除目标独有文件 | `copy` 原生支持 | 固定使用 copy，避免误选会传播删除的同步模式 |
| 覆盖历史 | `--backup-dir` 原生支持 | 自动设为目标旁的独立运行目录，按时间和随机标识命名 |
| 完整复核 | `check --one-way --download` 原生支持 | 正式复制结束后自动调用，报告失败时不称已完成 |
| 磁盘识别 | 命令按指定路径操作 | 增加本地卷序列号及目录标识绑定，发现换盘或换目录则停止 |
| 多组路径 | 用户自己管理命令/配置 | 按有方向的路径组合保存独立私有配置，复用已建立的磁盘绑定 |
| 并发与误操作 | 用户管理任务及参数组合 | 同目标独占锁、目录重叠检查、目标重解析点检查、隔离环境设置 |
| 使用状态 | 阅读 rclone 原始输出 | Codex 区分检查、复制和复核阶段，解释日志和估时的不确定性 |
| 历史恢复 | 自己选择文件和命令 | 先恢复到独立目录确认；不默认覆盖工作盘 |

rclone 本身也支持脚本化和自动化，上表中新增的是针对本地科研备份的固定策略、操作整合和自然语言入口，而不是 rclone 不具备自动化能力。
底层依据：[copy](https://rclone.org/commands/rclone_copy/)、[全局参数与 backup-dir](https://rclone.org/docs/)、[check](https://rclone.org/commands/rclone_check/)。

## 三层结构

```text
自然语言请求
    ↓
全局 Skill：理解路径、检查已有任务、预览、执行授权、解释结果
    ↓
job.py：按路径组合选择/建立本地配置
    ↓
backup.py：磁盘/路径检查、锁、版本目录、日志及成功状态
    ↓
rclone：比较内容、复制改动文件、归档旧文件、复核内容
```

技能全局安装于本机已被 Codex 识别的个人技能目录；`agents/openai.yaml` 明确允许自动匹配。
安装时写入私有 `runtime.local.json`，让任何工作目录中的聊天都能找到工具仓库。仓库移动后更新这个指针。
不要求每次聊天都记住本地仓库路径，也不把用户的磁盘路径写进公开技能说明。
技能既可显式调用也可按描述隐式匹配，这是 [Codex 官方技能文档](https://learn.chatgpt.com/docs/build-skills) 提供的机制；全局安装不能绕过当前聊天的磁盘访问权限。

## 每次执行流程

1. 解析源与最终目标目录，明确是单向备份；读取已存在任务和目标锁，避免重复启动。
2. 优先复用相同路径的既有绑定。新组合保存到 `profiles/路径组合哈希.local.json`，不覆盖其他任务配置。
3. 快速预览使用大小和修改时间；完整预览可以单独选择。预览统计不等于实际已传输。
4. 检查目标空闲容量，默认保留所有目标独有文件和被覆盖旧版本。
5. 正式运行默认用内容校验和比较；复制结束后逐字节复核源文件对应内容。
6. 小任务直接等结果。长任务隐藏后台运行，记录进程、起始时间和日志；正在运行与已验证成功必须区分。
7. 瞬时错误诊断后最多自动重试一次；身份不符、磁盘满、权限错误不反复重试，不自动重新绑定或删锁。

## 时间为什么可能比复制 36 GB 更久

本次源目录统计约 274 GiB、30.6 万个普通文件；快速预览约 36.3 GiB 需要更新。
当前严格模式包含：

- 检查：读取两边已存在文件，比较内容校验和。
- 复制：传输新增和不同内容的整个文件。
- 复核：读取源文件及目标对应文件进行逐字节比较。

因此只写入改动文件，也仍会读取大量未改动文件；增量减少写入量，不消除严格校验的读盘成本。
USB 硬盘随机读取、小文件数量、其他应用访问及缓存会影响速度。用当前阶段的速度和总量估计区间，不能按文件数量线性外推，也不能把复制 ETA 当成最终校验结束时间。
本次启动时的 6–12 小时是基于早期读盘表现的粗估，不是承诺或固定算法。进度变化后应重新估计，不写成每天必需时间。

默认保留严格模式。快速比较虽然省读盘，但可能漏掉大小和时间不变的内容变化；不能为了缩短时间静默降低校验等级。

## 发布与边界

公开 GitHub 保存代码、方案、测试和可安装技能；`config.local.json`、`profiles/`、日志、全局运行指针与实际研究文件不发布。
它支持 Windows 本地目录和移动硬盘普通文件副本，不是 VSS/数据库一致性快照，不备份 ACL/备用数据流，也不提供整目录时间点快照或分块去重。
源符号链接和目录联接按 rclone 默认规则跳过并警告；需要链接指向内容时应另行明确备份源，不能默默跟随链接扩大范围。
安装全局 Skill 负责让 Codex 知道何时、如何调用；真正的数据保护仍依赖 rclone、磁盘可靠性和实际复核结果。
